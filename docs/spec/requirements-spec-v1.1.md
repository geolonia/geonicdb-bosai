# 地方自治体 防災情報ウェブサイト 要件仕様書

- 文書番号：BOUSAI-WEB-SPEC-001
- 版：1.0（案）
- 作成日：2026年9月2日
- 対象：市区町村・都道府県が住民等に向けて運営する防災情報ウェブサイト（防災ポータル、災害時トップページ、ハザードマップ公開機能、避難所情報等を含む）

本書では要件の強度を次の記法で示す。

| 記法 | 意味 |
|---|---|
| **MUST** | 必須。満たさない場合は受入不可 |
| **SHOULD** | 原則対応。対応しない場合は理由を明示すること |
| **MAY** | 任意。自治体の規模・リスク特性に応じて選択 |

---

## 1. 目的と適用範囲

### 1.1 目的
災害発生前・発生時・復旧期の各フェーズにおいて、住民・来訪者・事業者・支援者が「命を守る行動に直結する情報」を、いつでも・どの端末でも・どの言語や身体条件でも、最短の操作で得られるウェブサイトを整備する。

### 1.2 適用範囲
- 防災ポータル（平時コンテンツ）
- 災害時トップページ（緊急モード）
- 避難情報・避難所情報の配信機能
- ハザードマップ等の地図機能
- 外部機関（気象庁、Lアラート、都道府県、ライフライン事業者等）とのデータ連携
- CMS・運用体制・BCP

### 1.3 想定利用者
| 利用者区分 | 想定される状況・ニーズ |
|---|---|
| 一般住民 | スマートフォンから避難情報・避難所・ハザードマップを確認 |
| 要配慮者（高齢者、障害者、乳幼児連れ、傷病者等） | 支援者による代理閲覧、スクリーンリーダー・拡大表示、福祉避難所情報 |
| 外国人住民・訪日旅行者 | 多言語／やさしい日本語、土地勘なしでの避難先把握 |
| 事業者・施設管理者 | 事業継続判断、従業員・利用者の避難誘導 |
| 報道機関・支援団体・他自治体 | 機械可読データ、オープンデータ、API |
| 庁内職員（災対本部・広報・各部局） | 迅速な更新、承認、他チャネルへの同時配信 |

## 3. 基本方針（設計原則）

1. **命を守る情報を最上位に**：避難情報（警戒レベル）、避難所開設状況、現在地のリスクを、トップページの最初の1画面（スマートフォン）で把握できること。
2. **平時と災害時のモード切替**：災害時は自動または1操作で「緊急モード」に切り替わり、平時の告知・イベント等は下位へ退避。
3. **誰一人取り残さない**：アクセシビリティ（JIS X 8341-3 AA／WCAG 2.2 AA）、多言語、やさしい日本語、色覚多様性、低リテラシー、低速回線・古い端末への配慮。
4. **止まらない・軽い**：静的配信＋CDNを基本とし、アクセス集中・停電・回線輻輳時も表示できる軽量ページを常備。
5. **一度の入力で多チャネルへ**：CMS入力を起点に、Lアラート、SNS、防災アプリ、緊急速報メール原稿、防災行政無線原稿、オープンデータ、APIへ同時展開。
6. **機械可読・オープン**：人間向け表示と同時に、CAP／JSON／GeoJSON／CSVで第三者（報道、アプリ開発者、他自治体、国のデータ連携基盤）が利用可能な形で公開。
7. **標準・オープン技術優先**：ベンダーロックインを避け、国際標準（WCAG、CAP、GeoJSON、OGC、NGSI-LD等）とOSS（MapLibre等）を優先。

## 4. 機能要件

### 4.1 トップページ・緊急モード

| ID | 要件 | 強度 |
|---|---|---|
| F-01 | 発災時、トップページ上部に「現在発令中の避難情報」「開設中の避難所」「本市の現在の体制（災対本部設置等）」を、警戒レベル色と文字ラベルで表示する | MUST |
| F-02 | 緊急モードへの切替はCMS上の1操作（またはLアラート／SOBO-WEB連携による自動切替）で行え、切替時刻・操作者を記録する | MUST |
| F-03 | 緊急モードでは平時コンテンツ（イベント、広報等）を非表示または下位へ移動し、ページ総容量を軽量化する（目安：初期表示 500KB 以下、外部スクリプト最小化） | MUST |
| F-04 | 緊急情報の「発表時刻」「最終更新時刻」「発表主体」「対象地域（地区名）」「とるべき行動」を明示する（ISO 22322 の警報要素に準拠） | MUST |
| F-05 | 画像・地図が読み込めない環境向けの「テキスト版」ページを常時提供し、トップから1タップで到達可能とする | MUST |
| F-06 | 平常時は「災害は発生していません／発令中の避難情報はありません」と明示し、最終確認時刻を表示する | SHOULD |
| F-07 | 訓練時の表示に「訓練」ラベルを付与できるモードを備える | SHOULD |

### 4.2 避難情報（警戒レベル）の配信

| ID | 要件 | 強度 |
|---|---|---|
| F-10 | 内閣府ガイドラインの区分（警戒レベル3「高齢者等避難」、レベル4「避難指示」、レベル5「緊急安全確保」）と名称を用い、独自名称を使わない | MUST |
| F-11 | 警戒レベル色は内閣府の標準（1白、2黄、3赤、4紫、5黒）を用い、色に加えて数字・文字・アイコンで区別する（ISO 22324／WCAG 1.4.1） | MUST |
| F-12 | 発令単位（地区・町丁目・小学校区等）ごとに発令状況を一覧および地図で表示し、住所・地区名からの検索を提供する | MUST |
| F-13 | 対象災害種別（洪水、土砂災害、高潮、津波、内水、火山等）を明示する | MUST |
| F-14 | 発令・切替・解除の履歴を時系列で閲覧できる | SHOULD |
| F-15 | 気象庁の警報・注意報・キキクル（危険度分布）、指定河川洪水予報、土砂災害警戒情報等を警戒レベル相当情報として併記し、気象庁の情報体系の変更に追随できる構成とする | MUST |
| F-16 | 「今、何をすべきか」（避難行動の要否、避難先の考え方、在宅避難・垂直避難の可否）を平易な文で表示する | MUST |

### 4.3 避難所・避難場所情報

| ID | 要件 | 強度 |
|---|---|---|
| F-20 | 指定緊急避難場所と指定避難所を区別し、対象災害種別ごとの適否（洪水○、土砂×等）を表示する | MUST |
| F-21 | 開設状況（開設／閉鎖／開設準備中）、開設時刻、混雑状況（空き／混雑／満員）を表示し、CMSまたは避難所運営システム（デジタル庁モデル仕様書準拠）から更新できる | MUST |
| F-22 | 施設属性：住所、電話、収容人数、バリアフリー（段差、多目的トイレ、エレベーター）、福祉避難所該当、ペット同行可否、授乳・更衣スペース、Wi-Fi、電源、駐車場、車中泊可否 | MUST |
| F-23 | 現在地または指定地点から近い避難所を距離順に表示し、地図と経路（外部地図アプリ連携可）を提供する | MUST |
| F-24 | データは「自治体標準オープンデータセット」の指定緊急避難場所一覧スキーマに準拠し、CSV／GeoJSON／APIで公開する | MUST |
| F-25 | 避難所ごとの物資・給水・充電・入浴支援・医療救護所等の付帯情報を掲載できる | SHOULD |
| F-26 | 男女共同参画の視点（相談窓口、女性専用スペース、防犯体制）に関する情報項目を備える | SHOULD |

### 4.4 ハザードマップ・地図機能

| ID | 要件 | 強度 |
|---|---|---|
| F-30 | 洪水（想定最大規模・計画規模）、内水、土砂災害警戒区域・特別警戒区域、津波、高潮、火山、地震（震度・液状化）等、当該自治体に関係するハザード情報を地図上に重ね合わせ表示できる | MUST |
| F-31 | 避難情報の発令区域、避難所、道路通行止め、浸水実績等のリアルタイム／準リアルタイム情報を同一地図上に重ね合わせできる | MUST |
| F-32 | 現在地取得（利用者の許諾のもと）、住所検索、地区名検索から地点を特定し、その地点の想定浸水深・区域該当等をテキストでも表示する（地図が見えない利用者への代替） | MUST |
| F-33 | ベース地図は地理院タイル等の公的基盤またはオープンな地図配信を基本とし、ハザードレイヤは国土地理院ハザードマップポータル・国土数値情報・自治体GISデータを利用する | SHOULD |
| F-34 | 地図実装はWeb標準（MapLibre GL JS等のOSS、ベクトルタイル、GeoJSON、OGC API）を用い、特定ベンダー固有形式に依存しない | SHOULD |
| F-35 | キーボード操作、ピンチ・ズームの代替（＋／－ボタン）、凡例の常時表示、色覚多様性に配慮した配色（国交省手引きの浸水深カラーと整合）を実装する | MUST |
| F-36 | PDF版ハザードマップ（印刷用）とウェブ地図版の両方を提供し、PDFにはテキスト情報（凡例・注意事項）を付与する | MUST |
| F-37 | 3D都市モデル（PLATEAU）等を用いた浸水シミュレーション表示 | MAY |

#### 5.8.2 HTTP Observatory の各テストに対応する仕様

Observatory は基準点 100 から減点し、基準点が高い場合のみ加点される方式である。すべての減点を回避し、加点対象（厳格な CSP、SRI 等）を満たす。

| Observatory テスト | 要件 | 強度 |
|---|---|---|
| Content Security Policy | `Content-Security-Policy` を HTTP ヘッダで送出（`<meta>` 不可）。`default-src 'none'` を起点としたホワイトリスト方式。`script-src` に `'unsafe-inline'`・`'unsafe-eval'`・ワイルドカードを含めない（nonce または hash と `'strict-dynamic'` を使用）。`style-src` にも `'unsafe-inline'` を含めない（加点条件）。`object-src 'none'`、`base-uri 'none'`、`frame-ancestors 'none'`（または `'self'`）、`form-action 'self'` を指定。`upgrade-insecure-requests` を併用 | MUST |
| Cookies | 公開サイトでは原則 Cookie を発行しない。発行する場合は `Secure; HttpOnly; SameSite=Lax`（または `Strict`）を必須とし、セッション Cookie は `__Host-` プレフィックスを付与 | MUST |
| Cross-origin Resource Sharing | `Access-Control-Allow-Origin: *` は公開オープンデータ・API エンドポイントに限定し、HTML ページには付与しない。認証情報付き CORS は使用しない | MUST |
| Redirection | HTTP → HTTPS へ同一ホストで 301 リダイレクトし、その後の HTTPS レスポンスで HSTS を返す。HTTP のまま別ホストへ転送しない | MUST |
| Referrer Policy | `Referrer-Policy: strict-origin-when-cross-origin` 以上（`no-referrer` または `same-origin` 推奨） | MUST |
| HTTP Strict Transport Security | `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`（2 年以上）。全サブドメインの HTTPS 化を確認したうえで HSTS Preload List に登録 | MUST |
| Subresource Integrity | 外部オリジンから読み込む `<script>`・`<link rel=stylesheet>` すべてに `integrity` 属性と `crossorigin` を付与。原則として JS／CSS は自ホスト（または自 CDN）から配信し、外部オリジン依存を排除 | MUST |
| X-Content-Type-Options | `X-Content-Type-Options: nosniff` | MUST |
| X-Frame-Options | `X-Frame-Options: DENY`（CSP `frame-ancestors` と併記） | MUST |
| Cross-Origin Resource Policy | `Cross-Origin-Resource-Policy: same-origin`（公開データ API は `cross-origin`） | MUST |

追加で以下を送出する（加点・他ツール対策）。

| ヘッダ | 値 | 強度 |
|---|---|---|
| Permissions-Policy | 使用しない機能を明示的に無効化。例：`camera=(), microphone=(), payment=(), usb=(), interest-cohort=()`。地図の現在地機能のため `geolocation=(self)` のみ許可 | MUST |
| Cross-Origin-Opener-Policy | `same-origin` | SHOULD |
| Cross-Origin-Embedder-Policy | `require-corp`（または `credentialless`）。外部タイル・画像の CORP 対応を確認できる場合のみ | MAY |
| Cache-Control | 静的資産は `public, max-age=31536000, immutable`（ファイル名にハッシュ付与）。HTML は `no-cache` または短い `s-maxage` ＋ CDN パージ | MUST |
| Server／X-Powered-By | 製品名・バージョンを出力しない（削除または汎用値） | MUST |
| X-XSS-Protection | 送出しない（非推奨。CSP で代替） | SHOULD |

**地図ライブラリと CSP の両立**：MapLibre GL JS 等の WebGL 地図は Worker と blob URL を使用するため、`worker-src 'self' blob:`、`child-src blob:`、`img-src 'self' data: blob: <タイル配信ホスト>`、`connect-src 'self' <タイル・スタイル・フォント配信ホスト>` を許可する。`script-src` に `blob:` を追加する必要が生じる場合は、ライブラリのビルド設定（Worker の分離ファイル化）で回避する。導入時は `Content-Security-Policy-Report-Only` と `report-to` で違反を収集し、段階的に強制モードへ移行する（**MUST**）。

## 7. 付録

### 7.1 警戒レベルと表示の対応（内閣府ガイドライン準拠）

| 警戒レベル | 住民がとるべき行動 | 市町村の避難情報等 | 標準色 |
|---|---|---|---|
| 5 | 命の危険 直ちに安全確保 | 緊急安全確保（必ず発令されるものではない） | 黒 |
| 4 | 危険な場所から全員避難 | 避難指示 | 紫 |
| 3 | 危険な場所から高齢者等は避難 | 高齢者等避難 | 赤 |
| 2 | 自らの避難行動を確認 | （気象庁 注意報等） | 黄 |
| 1 | 災害への心構えを高める | （気象庁 早期注意情報） | 白 |

※ 表示は色に加えて必ずレベル数字と名称を併記する。

### 7.2 用語

- **指定緊急避難場所**：災害の危険から命を守るために緊急に避難する場所（災害種別ごとに指定）
- **指定避難所**：災害により住居を失った等の場合に一定期間滞在する施設
- **Lアラート**：自治体等の災害情報を放送事業者・アプリ事業者等へ一斉配信する共通基盤
- **CAP**：警報情報を交換するための国際的なXML標準
- **SOBO-WEB**：内閣府の新総合防災情報システム
- **キキクル**：気象庁の危険度分布（土砂・浸水・洪水）

### 7.3 留意事項

- JIS X 8341-3はWCAG 2.2相当への改正が進行中であり、調達仕様では「現行JIS AA準拠かつWCAG 2.2 AAの追加基準に対応、改正JIS発行後は当該版に移行」と記載することを推奨する。
- 気象庁の防災気象情報体系は名称・区分の見直しが行われるため、表示名称・凡例はデータ駆動（設定変更）で追随できる実装とすること。
- 国の防災分野データ連携基盤は本格運用へ移行する段階にあり、連携要件は運用開始後の公開仕様に合わせて改定する。
- 本仕様は汎用的な要件を示すものであり、各自治体は地域防災計画・ハザード特性・住民構成に基づき数値目標（同時アクセス数、対応言語等）を確定すること。
