# 支援技術シナリオ（雛形）

導入自治体が公開前に実施する手動試験の手順例。テンプレート開発時の自動検査（axe）は補完であり、本シナリオの代替ではない。

環境例: NVDA + Firefox / VoiceOver + Safari / TalkBack + Chrome。OS・AT・ブラウザの版を試験結果に記録する。

## 共通前提

- 対象: トップ `/`、方針 `/accessibility/`、試験結果 `/accessibility/test-results/`
- キーボードのみ（マウス無し）でも完了できること
- 文字サイズ 200%・OS のコントラスト反転で情報が欠けないこと（N-05）

## シナリオ

### S1. トップの言語切替と見出し構造

1. ページ先頭から Tab で「表示言語」へ到達できる。
2. 支援技術がラベル「表示言語」と現在の言語名を読む。
3. 言語を切り替えたあと、主要な見出し（警戒レベル・クイックリンク・お知らせ）が読み上げ順で辿れる。

合否: 【要記入】 / 環境: 【要記入】

### S2. 緊急バナーの状態通知

1. 緊急系バリアント表示時、`role="alert"` / `aria-live="assertive"` により見出し・本文が読み上げられる（フォーカス移動なしでも分かる）。
2. 平時「お知らせ」は `role="status"` / `aria-live="polite"`。
3. バナー内リンクがある場合、キーボードで活性化できる。色だけに依存せず文言が読める。

合否: 【要記入】 / 環境: 【要記入】

### S3. 警戒レベルの理解（色覚・読み上げ）

1. レベル数字とラベル・行動文言が読み上げられる（色名だけに依存しない）。
2. レベル2（黄）でも文字が識別できる（コントラスト）。

合否: 【要記入】 / 環境: 【要記入】

### S4. フッターの一貫したヘルプ（3.2.6）

1. トップ・方針・試験結果の各ページで、フッターに「方針」「試験結果」「問い合わせ」が同じ順序で存在する。
2. 各リンクをキーボードで開き、目的のページに到達する。

合否: 【要記入】 / 環境: 【要記入】

### S5. 方針・試験結果ページの文書構造

1. `h1` が1つでページ主題を表す。
2. JB.3.1 各項目（表明日〜試験実施期間）が定義リストまたは同等の構造で辿れる。
3. 「【要記入】」が残っている場合、公開前に実値へ置換したことを確認する（テンプレート配布時点の残存は可）。

合否: 【要記入】 / 環境: 【要記入】

### S6. 地図・グラフ・PDF・動画（該当コンテンツがある場合）

1. 地図: 同等の一覧・表が地図の近くにあり、キーボードで利用できる（N-04）。
2. PDF: テキスト選択・読み上げ可能。重要情報は HTML でも提供（N-06）。
3. 動画: 字幕または書き起こし。音声のみ: テキスト代替（N-07）。

合否: 【要記入】 / 該当なし: 【要記入】
